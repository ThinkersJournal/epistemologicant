# EpistemologicAnt: seed of the spec (PM draft of 2026-11-18, for the lane to expand and CireSnave to mark up)

Facts are marked **[said]** (CireSnave) or **[PM]** (the PM's proposal). Nothing here is verified against the literature or the crate ecosystem:
that survey is the lane's first job.

## 1. What it is
- **[said]** A set of comprehensive tool libraries covering the entire field of epistemology (the theory of knowledge) and its analysis.
- **[said]** Toolsets that AnalysAnt's lenses use, not the lenses themselves; other projects may depend on them too.
- **[said]** When a project needs a tool in this field, the tool is built here and used as a dependency.

## 2. Scope [PM]
- knowledge, belief and degrees of belief; justification and evidence; truth and certainty
- testimony, source reliability and track records; independence of evidence (when two sources really are two)
- defeaters (rebutting and undercutting); coherence and foundations; contradiction
- belief revision (expansion, contraction, revision) and what a revision must keep
- trust and credibility: how trust is built, lost and recovered

## 3. First tool candidates [PM]
- an evidence and corroboration calculus with an independence test, generic over any body of claims and sources (a source cannot corroborate itself or lift its own standing through sources that only cite each other); SageAnt's trust ratings are ONE use of it, not its shape
- a source-reliability model, generic over any kind of source (a person, a tool, a site, an agent, a model): a record of outcomes per identity and per topic, shrunk toward an unknown-source baseline while evidence is thin, recency-weighted so a source can recover
- belief-revision operations over a set of claims with explicit reasons
- an argument structure with rebutting and undercutting defeaters (for AnalysAnt's epistemic lens)

## 4. Consumers [PM]
- SageAnt (trust and confidence, X3: the FIRST consumer; its design note references this project)
- AnalysAnt (the epistemic lens, `analysant-epistemic`)

## 5. Principles [PM]
- Generic over any use of the tool type (CireSnave 2026-11-18: "tools should be built to be generic over any use of that tool type and not specific to the individual consumer"): a consumer's needs are requirements and test cases, never the shape of the API; a tool must serve every plausible use of its kind.
- Deterministic first: rules, tables and data packs before any model; a model, if ever, is an optional escalation behind a trait. No model inside the core.
- Explainable: every verdict carries its reasons, so a human can check it.
- Small, separate crates inside one project: one version number for the project; a core of shared types plus one crate per tool family.
- Language as data: nothing hard-coded to English; Rust is the second language so text can be checked against code.
- Safe Rust (`#![forbid(unsafe_code)]`), standard-library-only core where possible, permissive-licence dependencies only.
- Every claim in a README or doc is earned: built, tested, and checked against the code.
